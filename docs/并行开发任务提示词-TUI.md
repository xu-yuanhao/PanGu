## 3. 双方接口约定 v0（内部源码接口，尚非稳定插件 ABI）

主 Agent 负责最终公共 C 头文件 `src/contracts/client.h`。你先按以下语义实现客户端内部适配；头文件未出现时可在你的测试目录放临时适配声明。禁止在产品客户端硬编码第二份共享头文件。最终由主 Agent 提供桥接、消除临时声明并编译集成。

客户端向 Runtime 提交三个动作：

1. `submit`：完整 UTF-8 用户文本（指针+显式字节长度），Runtime在返回前复制需要保留的输入；忙时拒绝，输入内容仍留在编辑器里。
2. `cancel`：请求取消当前运行，可重复；不等于已经完成，不立刻把 UI 标为闲置。
3. `poll`：推进有限工作量，并拉取事件；返回无事件时客户端等待输入/下次推进，不忙循环。具体函数签名由主 Agent 在集成时固定。

Runtime 向客户端输出按顺序的事件：`run_started`、`text_delta`、`tool_started`、`tool_finished`、`run_finished`。错误和取消通过唯一的 `run_finished` 终态表达，终态为 success/error/cancelled。工具事件携带稳定调用 ID、工具名；完成事件有成功/错误与简短内容；文本携带指针+字节长度。事件字符串只在当前处理调用期间有效，客户端若保留须复制到有界存储。

单客户端、单线程、同一时间一个活动 run。每个 run 恰好一个终态，客户端不自行补造成功终态。终态前收到取消请求仍可显示实际到达的事件。输入和展示缓冲必须有明确上限；过长输入明确拒绝，展示截断明确标记。主 Agent 负责整个系统的上限协调。

你可以设计私有渲染/输入函数，但不要把上述语义擅自扩大成 RPC 协议、线程池或公共事件总线。若出现接口问题，记录最小建议，适配先留在你独占目录，主 Agent最后确认。
