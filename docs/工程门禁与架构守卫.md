# 盘古工程守卫

## 实现边界

| 检查点 | 执行要求 | 现有检查入口 |
|---|---|---|
| 技术栈 | 核心与 TUI 纯逻辑为手写 Assembly；C/C++ 的外部桥接用途逐模块登记 | `governance/assembly-first.json`、`tools/gates/assembly_first.py` |
| 来源 | 对照 TODO 指定的上游函数、调用者及测试，实现相同用户行为 | 两份 TODO 的来源与交接记录 |
| 服务组合 | Host 负责解析依赖与生命周期；业务通过注入的服务接口运行 | 实际公开头、模块依赖、替换测试 |
| 内存 | 显式长度、容量、分配/释放方、借用有效期；失败路径释放资源 | 受影响的 ABI、保护页、故障用例 |
| 持久化 | 提交确认后采纳；取消、暂停和重开使用持久状态 | Session/Storage/恢复专项 |
| 工具 | 参数校验、授权、执行顺序固定；工作目录、输出与取消可验证 | 工具专项和临时工作区真实闭环 |
| 凭据 | 通过配置/认证服务注入，日志和会话仅保存公开身份 | 请求、日志与子进程环境检查 |
| 并行 | 按 AGENTS 的文件归属修改；公共接口由核心维护 | 两份 TODO 的交接区 |

## 执行批次

核心按核心 TODO 的 B01–B05 批次组织 K01–K15，TUI按 U01–U08 的完整交互组推进。每批先写清实际调用者、交付行为、受影响文件和对应上游用例，再连续完成成组移植、产品接线和修复。基础接口与所有权根据当前消费者确定。

验收以实际状态、事件、存储和副作用为依据。参考已有用例优先移植为原生场景；故障注入覆盖本次新增的分配、提交和释放风险。真实模型用于已接通的对话、工具、取消和恢复工作流。

## 验证时机

| 时机 | 运行内容 | 结束条件 |
|---|---|---|
| 开发修改 | 当前受影响模块/场景；失败后修复并复跑相关项 | 本次行为与对应参考用例一致 |
| ABI、所有权或提交边界变化 | 直接消费者、相关内存/失败路径检查 | 数据、布局、释放和首因一致 |
| 文件/模块登记变化 | G00；产品源或语言职责变化同时检查 Assembly | 清单与实际构建一致 |
| 检查器变化 | 对应检查器自测 | 检查规则有效 |
| 执行批次集成 | Runtime 全套、产品构建；涉及TUI时加客户端/PTY | 批次调用链可运行且现有行为保持 |
| K15/U08 | 全部覆盖核对及完整真实模型TUI工作流 | 完整移植验收成立 |

一次通过的结果对应其源版本；后续修改按依赖选择重跑范围。完整回归集中在执行批次集成点。测试通过后继续本批移植；追加检查由具体失败、变更风险或尚未覆盖的上游行为驱动。

TUI专项由TUI Agent维护，Runtime专项与整机组合由核心维护。公共接口通过独立入口扩展，既有调用者可持续构建；联调时统一迁移共享布局。

## 测试维护

回归测试随当前产品行为维护，优先复用上游场景。删除已经退出构建且无消费者的历史实验、可由现有用例覆盖的重复检查和可再生成的冗余夹具，并同步清理构建与登记。测试保留依据是当前行为覆盖与独立检错价值。生成的大型语料写入临时目录。

## 登记与自审

- `governance/bootstrap-policy.json`：文件清单。
- `governance/assembly-first.json`：实际产品构建源与语言职责。
- `governance/runtime-local-modules.json`：服务、模块、依赖与来源。
- 公开头文件：实际 ABI、所有权、借用与清理契约。

采用的上游代码/数据随模块保留来源与许可证。新增文件、接口和依赖随实现登记。控制配置变更由实施 Agent 自审，使用 Git diff/提交标识与实际检查结果记录结论。交接记录保留当前来源、实现、结果、具体缺口和下一交付物；已完成批次的历史由 Git 保存。保持现有测试、边界和参考基线可核对。
