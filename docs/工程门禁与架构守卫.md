# 盘古工程守卫

## 实现边界

| 检查点 | 执行要求 | 现有检查入口 |
|---|---|---|
| 技术栈 | 核心与 TUI 纯逻辑为手写 Assembly；C/C++ 的外部桥接用途逐模块登记 | `governance/assembly-first.json`、`tools/gates/assembly_first.py` |
| 来源 | 对照 TODO 指定的上游函数、调用者及测试，实现相同用户行为 | 两份 TODO 的来源与交接记录 |
| 服务组合 | Host 负责解析依赖与生命周期；业务通过注入的服务接口运行 | 实际公开头、模块依赖、替换测试 |
| 内存 | 显式长度、容量、分配/释放方、借用有效期；失败路径释放资源 | 受影响的 ABI、保护页、故障用例 |
| 持久化 | 提交确认后采纳；取消、暂停和重开使用持久状态 | Session/Storage/恢复专项 |
| 工具 | 参数校验、授权、执行顺序固定；工作目录、输出与取消可验证 | 工具专项和临时工作区真实闭环 |
| 凭据 | 通过配置/认证服务注入，日志和会话仅保存公开身份 | 请求、日志与子进程环境检查 |
| 并行 | 按 AGENTS 的文件归属修改；公共接口由核心维护 | 两份 TODO 的交接区 |

## 每批工作

1. 选自己 TODO 中依赖已满足的下一步骤，定位上游实现与测试。
2. 确定源模块到原生文件的映射，说明所用服务、所有权、错误和取消路径。
3. 在现有模块中完成一个可运行行为，连同直接相关测试维护。
4. 运行受影响模块专项；涉及跨模块集成时再运行对应集成入口。
5. 完成文件登记与 `python3 -B tools/gates/check.py`，勾选已满足全部验收条件的步骤。

TUI Agent 运行客户端专项，核心 Agent 负责 Runtime 专项和全程序组合。整机检查在接口集成后集中运行。真实模型用于对话、工具、取消、恢复等完整工作流；确定性用例验证协议、状态、内存和错误边界。

## 现有命令

```bash
python3 -B tools/gates/check.py
python3 -B tools/gates/assembly_first.py
python3 -B tools/runtime/build_test.py
bash tools/client/tui/build.sh run-tests
python3 -B tools/runtime/build_pangu.py --output /tmp/pangu-native/pangu
python3 -B tools/runtime/test_pangu_pty.py
```

模型闭环使用现有测试的显式 `--live-*` 入口和环境凭据。测试产物写入临时目录。

## 登记与自审

- `governance/bootstrap-policy.json`：文件清单。
- `governance/assembly-first.json`：实际产品构建源与语言职责。
- `governance/runtime-local-modules.json`：服务、模块、依赖与来源。
- 公开头文件：实际 ABI、所有权、借用与清理契约。

采用的上游代码/数据随模块保留来源与许可证。新增文件、接口和依赖随实现登记。控制配置变更由实施 Agent 自审，记录本批差异、固定内容摘要、实际检查、风险和结论。保持现有测试、边界和参考基线可核对。
