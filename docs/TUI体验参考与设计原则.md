# TUI 体验参考与设计原则

日期：2026-10-20。状态：后续 T28/T33/T34 的设计方向，不是已实现界面或体验验收报告。参考快照见 [UI/UX 参考登记](migration/tui-ux-reference-baseline.json)。

## 参考结论

Grok Build 作为主要 UI/UX 参考，Pi 作为简洁性基线，Codex 与 Claude Code 补充输入、状态、工具与审批交互。这里选择的是适合盘古的体验方向，不声称 Grok 获得客观排名第一，也不一比一复刻任何产品。

本轮检索未找到这四款同版本、同任务、同终端条件下的可靠可用性排名。多数比较混合模型能力、价格和界面，不能把生成代码质量当作 TUI 优劣。主要依据如下：

- [Fazt 的实际试用（正文标注 2026-05-30）](https://fazt.dev/contenido/grok-build-review-xai-2026) 单独肯定 Grok Build 的 TUI、鼠标操作和流畅感，也谈及计划浏览。这是支持主参考选择的一份体验证据，不是四款横向测评。
- [Grok Build 官方仓库](https://github.com/xai-org/grok-build) 与快照中的键盘/配置/终端文档展示了全屏、简洁模式、焦点、滚动和折叠等可研究设计；功能存在不等于已验证盘古应全部采用。
- [2025-08 的 Codex/Claude Code 用户讨论](https://www.reddit.com/r/ClaudeCode/comments/1n5457g) 提到 Codex 的响应体验与 Claude Code 的卡顿。这是旧版本个体反馈，仅用于提醒长会话、闪烁和滚动测试，不能推断当前性能或编程语言决定体验。
- [2026-06 的 Claude Code 终端体验讨论](https://www.reddit.com/r/ClaudeCode/comments/1tydp2b/do_you_use_the_claude_code_tui_or_gui/) 有用户强调底部固定输入的价值。讨论中的具体命令与产品状态未独立验证，只提取“阅读历史时仍能输入”的用户需求。

没有实际安装运行这些产品进行四方对照，也没有测得延迟/帧率，不填写主观评分冒充实测。后续在盘古原型中比较相同用户任务，再决定具体布局与按键。

## 盘古默认体验

1. 启动后就能理解哪里输入、哪里看回答、当前在做什么；不要求先学 Vim、命令面板或多窗格。
2. 主界面只保留会话、输入和必要状态。工具执行先显示简短状态/结果，细节按需展开；错误和待批准动作保持可见。
3. 所有基本任务可仅用键盘完成。提供可发现的帮助提示；鼠标可增强选择、滚动与展开，但不是完成任务的前提。
4. 用户向上阅读时，流式更新不强行拉回底部；明确提供回到最新内容的入口，切换焦点不丢草稿。输入区在阅读历史时仍可访问。
5. 操作反馈及时、文字稳定，避免无意义整屏刷新、闪烁和高频动画；不能靠隐藏更新或最终文本来追求流畅。
6. 中文输入、组合字符、多行粘贴和窄终端必须可用；不把“默认英文终端能显示”当完成。
7. 取消、退出、关闭弹层是不同动作，提示须清楚；退出和错误恢复终端模式。审批说明具体动作与范围，不复制“默认全部允许”。
8. 基本语义不依赖颜色、图标或鼠标。高级能力逐步出现，默认不展示全套模型、会话、Agent 和配置控制面。

## 按阶段交付

| 阶段 | 必需交付 | 延后 |
|---|---|---|
| T28 / P1 | 输入/提交、基本中文与粘贴、流式文本、工具状态/结果、取消、resize、终端恢复；能完成对话→工具→续答 | 完整 Markdown 编辑器、复杂多面板、主题市场、多会话管理、Vim、动画装饰 |
| T33 | 在 T28 客户端上完善编辑、焦点、键盘/鼠标、终端兼容、CJK/emoji 与输入回放 | 不重写另一套 Runtime 或终端客户端 |
| T34 / P2 | 完善 Markdown/diff、历史、会话/模型选择、渐进展开和其他确有需求的日常交互 | 不以复制四家功能并集作为完成条件 |

全屏布局作为优先原型方向，先验证历史可读、输入可达与窄终端表现；必要时按终端能力提供简洁输出降级。T28 不为同时复刻两套完整渲染模式扩张工作量。非 TTY 使用明确的自动化入口，不假装交互终端存在。

## 实现与验收

TUI自身逻辑优先手写Assembly，C只承担必要平台/外部库胶水，C++不进入当前TUI；通过本项目终端PAL/ANSI能力完成。不得引入 Rust、React、Ink、Node 或任一家 TUI 框架作为产品运行时。也不为参考某个效果额外自研大型通用 UI 框架；原生依赖仍须按门禁登记。

每项参考形成“用户任务 → 观察到的设计 → 盘古方案 → 验收”的记录，不复制组件层级或全套按键表。至少用 PTY 输入回放验证：首次输入、中文/粘贴、流式中取消、长工具输出、查看历史时继续流式更新、窄窗口/resize、错误与退出恢复。截图只作布局证据，不能替代输入与状态测试。

首个原型请用户实际完成一次读/改/运行任务，记录找不到输入、焦点丢失、滚动跳动、工具状态难懂等问题。性能阈值基于真实原型测量后登记；目前不编造毫秒、FPS 或“零卡顿”承诺。
